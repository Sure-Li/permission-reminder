# 权限到期提醒工具

Windows 桌面运维小工具：读取《客户私募资管权限有效期》Excel，在每项权限
**到期日前推 5 个工作日**当天自动发送汇总提醒邮件（漏检自动补发）。

## 功能特性

- **邮箱配置**：发件邮箱、SMTP 服务器/端口、加密方式（SSL / STARTTLS / 不加密）、
  授权码、多个目标邮箱，一键保存到本地；内置 QQ/163/腾讯企业邮箱/自建邮局预设；
  支持发送测试邮件验证配置；**提供"清除邮箱配置"按钮**（只清邮箱相关，
  Excel 路径/定时/勾选保持不变）。
- **连接诊断（发信链路自检）**：连不上或发送失败时点一次即可定位到**具体哪一环断了**，
  不再只有一句 "timed out"。依次检查：配置完整性 → 端口与加密方式是否配套
  （443/80/993/143/110 等误填识别）→ 域名解析 → 端口连通性 → **服务号探测**
  （关键：区分"真有邮件服务"与"TCP 连得上却一个字节都不返回"的假连接）
  → 本机出站基线对照（区分"目标服务器不可达"与"本机被封 SMTP 出站"）
  → 发件域 **MX 记录查询**（纯 UDP DNS，无第三方依赖）
  → **MX 主机端点逐一实测**（找出哪台主机真的提供 SMTP，自建邮局场景的决定性一步）
  → 服务商识别（腾讯企业邮 / 网易 / 阿里 / 飞书 / Microsoft 365 / 自建 Coremail 等）
  → TLS 握手与**账号登录验证** → 收件人格式。
  结论区给出中文原因与处置步骤，并给出基于**实测结果**的**推荐 SMTP 配置**，
  可一键套用。诊断只做连通性/服务号/认证验证，**不发送任何邮件**；
  且当连接已被安全网关拒绝时**不会提交账号密码**（避免加重封禁）。
- **反封禁保护**：企业邮件安全网关（如 Coremail CACTER）会按来源 IP 统计认证
  失败次数并临时封禁。因此本工具：① 认证失败/被网关拒绝时**不重试**（一次即止）；
  ② 失败后进入 10 分钟**发送冷静期**，期内直接报错、不再触碰服务器；
  ③ 修改并保存邮箱配置、或一键套用推荐配置时自动解除冷静期。避免"手一抖多点几次
  就把公司出口 IP 送进黑名单"。
- **两条投递通道**：默认 **SMTP 直发**；若单位邮件网关拒绝第三方客户端认证
  （如 `535 reject by CACTER gateway`），可切换到 **本机邮件客户端** 兜底通道——
  只需目标邮箱，把汇总邮件导出为 `data\outbox\*.eml` + `.html` 并唤起邮件客户端投递；
  导出后弹窗确认是否真的发出，未确认则不标记已发、下次照常提醒。另有
  **导出邮件到本地**（只落盘不发送）与 **打开导出目录** 两个按钮。
- **客户汇总表与 Excel 附件**：同一客户的提醒合为一行，列为客户号、客户名称、
  专业投资者权限、私募基金权限、资管权限；命中的权限单元格显示到期日期，
  并保留补发与原提醒时点信息。每封提醒附带同结构的
  `权限到期YYYYMMDDHHMMSS.xlsx`，SMTP 直发和导出的 `.eml` 都包含附件。
- **Excel 表头识别**：读取第一个工作表，自动查找表头，兼容标题行和空白行；
  列名允许空格、换行，客户名称也可写作“客户姓名”或“客户名”，
  客户号也可写作“客户编号”。支持 `.xlsx` 和 `.xlsm` 文件。
- **Foxmail 集成**：自动定位本机 Foxmail 主程序（注册表三处 + 卸载信息 + 常见安装目录
  + `PATH`，也可手动指定），兜底通道投递时**优先用 Foxmail**而不是系统默认客户端
  —— 因为单位要求的账号凭据在 Foxmail 里，而系统默认的可能是个人版 Outlook。
  唤起方式三选一：**自动**（推荐）/ **打开导出邮件(.eml)** / **新建写信窗口(mailto)**；
  有 **测试唤起** 按钮可当场验证集成是否可用，**设为默认邮件程序** 按钮会打开
  Windows 默认应用设置页（由系统完成，本工具不写注册表）。
- **收件人格式校验**：保存配置、发送测试、执行检查三处都会先校验目标邮箱格式，
  像 `recipient@examplecom`（漏写域名的点）这类笔误会被**提前拦截并精确指出**，
  不再等到 SMTP 报错、白等 3 轮重试。
- **失败原因分型提示**：连接超时 / 域名解析失败 / 端口被拒 / TLS 不匹配 /
  收件人被拒 / 认证失败分别给出对应处置建议；腾讯（企业）邮箱会直接给出
  「客户端专用密码」的获取步骤。
- **节假日同步**：一键从在线数据源（timor.tech 节假日 API，备用 holiday-cn）
  同步最新法定节假日与调休补班安排，本地缓存后**优先用于工作日计算**；
  同步后自动弹出**休假计划窗口**，展示前后一个月（上月 1 号 ~ 下月最后一天）
  的休假与补班安排，也可用"查看休假计划"离线查看本地缓存。
- **检查前自动同步（默认开启）**：每次检查（立即检查 / 定时 / 启动补检）前都会
  先拉取一次最新节假日数据，保证工作日计算用的是最新安排；可在"节假日"区用
  **检查前自动同步** 复选框关闭。同步失败**仅记日志、不弹窗、不打断检查**，
  自动沿用本地缓存与内置数据，因此无网络环境可放心开启。
- **文件记忆**：选择 Excel 文件后路径持久化，下次启动自动加载；"清除设置文件"
  一键清空本地配置。
- **定时任务**：每天固定时:分自动检查，开关状态重启后自动恢复；错过时点
  （程序未开机等）在 3 天窗口内启动补发，邮件标注【补发】。
- **检查范围**：专业投资者 / 私募基金 / 资管权限三个到期日期列自由勾选。
- **智能去重**：同一客户同一权限同一触发日只发一次（手动/定时/补检共享记录）。
- **工作日计算**：优先级为 本地同步节假日数据 > chinese-calendar 包内置数据 >
  仅排除周末；超出数据年份自动降级并记录警告，预留 WorkdayCalendar 接口可扩展。
- **容错**：Excel 列缺失、日期格式混杂（`20261021` 数字 / 字符串 / datetime /
  Excel 序列号）、SMTP 失败重试 3 次指数退避，均有弹窗 + 日志友好提示。

## 环境要求

- Windows + Python 3.10 及以上（需包含 tkinter，官方安装包默认自带）
- 依赖见 `requirements.txt`：pandas、openpyxl、chinese-calendar

## 运行方法

```bat
:: 1. 进入项目目录，创建虚拟环境并安装依赖
cd permission_reminder
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

:: 2. 启动程序
.venv\Scripts\python app.py
```

## 使用说明

1. **配置邮箱**：填写 SMTP 信息（可先选预设）、发件邮箱、授权码（QQ 邮箱请使用
   "设置 → 账户"里生成的授权码而非登录密码）、目标邮箱（多个用英文逗号分隔），
   点击 **保存邮箱配置**；建议先点 **发送测试邮件** 确认能收到。
   若提示超时或认证失败，点 **连接诊断** —— 报告会指出断在哪一环；
   企业邮箱（如腾讯企业邮 / 网易企业邮）通常需要用服务商生成的
   **客户端专用密码 / 授权码**，不能填网页登录密码。

   **单位自建邮局（Coremail / Exchange 等）请特别注意**：
   - **发信服务器不是 `mail.<你的域名>`**，而是**发件域 MX 记录指向的那台主机**
     （例如 `mailex1.<你的域名>`），这类"mail.域名"往往只是负载均衡/Web 门户前端，
     连得上但根本不说 SMTP——点一次 **连接诊断**，它会查 MX 并**逐一实测**，
     直接把可用的端点填进"推荐配置"，一键套用即可；
   - **加密方式**：自建邮局常用 **25 端口 + STARTTLS**（本工具已支持）；
     若服务器不支持 STARTTLS，则选 **不加密**；
   - **密码**：若用网页登录密码认证被拒（535），请登录网页版邮箱 →
     设置 → 安全设置/客户端设置，生成**客户端专用密码 / 授权码**填入；
   - **别连点发送/测试**：网关会按出口 IP 统计认证失败次数并临时封禁
     （报 `554 ... Smtp auth error limit exceeded`）。本工具已内置 10 分钟冷静期
     与"失败不重试"策略来兜底，但请先确认密码再试；
   - **拿不到正确凭据时的应急通道**：把「发送方式」切到 **本机邮件客户端**——
     不需要授权码/密码，只填目标邮箱，工具会把提醒导出成 `.eml` 由你手动投递。
     这条通道**不碰 SMTP**，因此完全绕过网关的客户端认证策略；
   - **建议顺手做一次 Foxmail 集成**：在下面「Foxmail」一栏点 **自动检测**，
     检测到后点 **测试唤起** 验证一下。集成后本工具会**直接用 Foxmail 投递**，
     不再依赖系统默认邮件程序（避免电脑上默认的是个人版 Outlook）。
     若尚未安装 Foxmail，请先安装并在其中配好单位邮箱账号，再回来点 **自动检测**。
2. **选择数据文件**：点击 **选择 Excel 文件**，选中 `.xlsx` 或 `.xlsm` 客户权限有效期表。
   程序自动识别包含客户号、客户姓名和三项权限到期日期的表头行，
   日期列兼容 `20261021` 数字等多种格式。
3. **勾选检查范围**：默认三项全查，可按需取消勾选。
4. **节假日**：保持 **检查前自动同步** 勾选（默认开启）即可，程序会在每次检查前
   自动拉取最新放假与调休安排并缓存到本地。也可手动点 **同步最新节假日**
   立即拉取并弹出 **休假计划** 窗口，列出前后一个月的休假/补班明细
   （绿色为休、红色为补班）。无网络时点 **查看休假计划** 只看已有缓存与内置数据。
5. **设置定时**：调整时/分，点击 **启动定时任务**。程序需保持运行；关闭程序后
   定时停止，重新打开会自动恢复调度并补检漏掉的提醒。
6. **立即检查**：随时点击 **立即检查并发送提醒** 手动跑一次（与定时共享去重）。

### 发送方式二选一（邮箱配置区第四行）

| 方式 | 何时用 | 需要填什么 |
|------|--------|-----------|
| **SMTP 直发**（默认） | 正常情况 | 服务器 + 端口 + 加密方式 + 发件人 + 授权码 + 目标邮箱 |
| **本机邮件客户端** | 单位邮件网关拒绝第三方客户端认证（如 `535 reject by CACTER gateway`），一时拿不到客户端专用密码 | **只需目标邮箱**（不需要服务器/授权码/密码） |

选「本机邮件客户端」后，每次检查会：

1. 把汇总邮件导出到 `data\outbox\` 目录，生成一对同名文件
   （`权限到期提醒_20261014-093000.eml` + `.html`，同秒多次导出会自动加 `-1` 序号，不覆盖）；
2. 唤起邮件客户端投递 —— **优先 Foxmail**（已集成时），否则用系统默认邮件客户端；
3. 弹窗问你**是否已成功发送**——选「是」才标记为已发；选「否」不标记，
   下次检查会再次提醒（邮件是否真的发出只有你知道，工具不替你假设）。

投递目标的选择顺序，以及各自的处理：

| 优先级 | 情况 | 工具行为 |
|---|---|---|
| ① | **已集成 Foxmail** | 唤起 Foxmail 打开导出的 `.eml`（或弹写信窗口），由它用自己配好的单位账号投递 |
| ② | 未集成 Foxmail，但有 `.eml` 关联程序 | 打开完整 `.eml` 邮件（含正文与 Excel 附件），由用户再次编辑或转发投递，并提示去做 Foxmail 集成 |
| ③ | 两者都没有 | **不唤起任何窗口**，直接打开导出目录，请手动双击 `.eml` 发送 |

### Foxmail 集成（邮箱配置区第五、六行）

| 控件 | 作用 |
|---|---|
| **Foxmail 路径** | 显示 Foxmail.exe 的完整路径；启动时自动探测并回填，也可手工改 |
| **自动检测** | 重新扫描并定位 Foxmail 主程序（用户指定 → 注册表 → 卸载信息 → 常见目录 → PATH） |
| **浏览…** | 手动指定 Foxmail.exe（装在非默认位置时用） |
| **测试唤起** | 导出一封测试邮件并唤起 Foxmail，**当场验证集成是否真的可用**（不会自动发送） |
| **唤起方式** | `自动`（有 .eml 就用它，否则用 mailto）/ `打开导出邮件(.eml)` / `新建写信窗口(mailto)` |
| **设为默认邮件程序** | 打开 Windows「默认应用」设置页，由系统把 Foxmail 设为 `MAILTO` 程序 |

三种唤起方式的取舍：

正式到期提醒含有 Excel 附件，投递时会使用完整的 `.eml` 邮件文件；
即使选择了 `mailto`，Foxmail 也会改为打开 `.eml`。系统没有 `.eml` 关联程序时，
会打开导出目录供手动投递。下面的 `mailto` 方式适用于不带附件的测试邮件。

- **打开导出邮件(.eml)**（默认，最可靠）：`Foxmail.exe "……\权限到期提醒_xxx.eml"`。
  只是"用某个程序打开某个文件"，**不依赖任何私有命令行参数**，兼容性最好；
  在 Foxmail 里点「转发 / 再次编辑 → 发送」即完成投递。
- **新建写信窗口(mailto)**：`Foxmail.exe "mailto:…?subject=…&body=…"`，
  直接弹出新建邮件窗口并预填内容，少一步点击，但依赖 Foxmail 对 mailto 作为启动参数的支持。
- **自动**：有 `.eml` 时用前者，没有时退回后者。

> 若某种方式在你这台机器上没反应，把「唤起方式」换成另一种再点 **测试唤起** 试一次即可。
> 集成只负责**唤起**，最后一步的「发送」始终由你在 Foxmail 里点 —— 所以工具不会替你把
> 邮件当成"已发送"。

关于"系统默认邮件客户端"：工具会先用 Windows 的关联查询接口探测它到底是
Foxmail、Outlook 还是 Windows 自带邮件应用，并在提示里写清楚，
**避免"以为在发 Foxmail、实际弹了别的东西"**。特殊情况：

- **没有设置默认邮件客户端**：此时点 `mailto:` 只会弹出 Windows 的「选取应用」框，
  毫无帮助，所以工具**不会去打开它**，改为自动打开导出目录，
  请手动双击 `.eml`（用 Foxmail 等已配好单位账号的客户端）发送；
- **默认客户端不是单位邮箱**（例如是个人 Microsoft 账号的「新版 Outlook」）：
  请改用 Foxmail 打开导出的 `.eml` 发送，或用上面的 Foxmail 集成让工具直接走 Foxmail。

> ⚠️ 提醒邮件含**客户号与客户姓名**，请务必用**单位邮箱**发送，不要使用个人邮箱。

为什么这样能绕开网关：投递由 Foxmail/Outlook 用它自己已经配置好、能正常发信的凭据完成，
本工具完全不碰 SMTP，因此不涉及第三方客户端的认证策略。

其他按钮：

- **导出邮件到本地**：只导出 `.eml` + `.html` 并核对排版，**不发送、不标记已发**；
- **打开导出目录**：直接用资源管理器打开 `data\outbox\`，可把 `.eml` 拖进 Foxmail 或双击打开后发送。

`mailto:` 唤起的新建邮件窗口正文有长度上限（各客户端约 2000 字符），超长会自动截断并提示
以导出的 `.eml` / `.html` 为准。

提醒规则：到期日前推 5 个工作日（排除周末和法定节假日）当天触发，一封汇总
邮件列出所有命中项，主题固定为【权限到期提醒】。

## 文件说明

```
app.py                    程序入口
permission_reminder/
  ui/main_window.py       界面层（tkinter）
  ui/holiday_window.py    休假计划展示窗口
  ui/diag_window.py       发信诊断报告窗口（可复制、可一键应用推荐配置）
  core/excel_reader.py    Excel 读取与日期解析
  core/workday.py         工作日计算（本地节假日 > chinese-calendar > 仅周末）
  core/holiday_sync.py    节假日在线同步与本地缓存（手动 + 检查前自动，共用同步锁）
  core/checker.py         触发判断 + 发送记录去重
  core/scheduler.py       定时调度后台线程
  mailer/sender.py        邮件发送（SSL/STARTTLS/不加密、错误分型、反封禁冷静期）
                          与正文渲染、收件人校验
  mailer/diagnose.py      发信链路诊断（服务号探测、MX 端点实测、假连接识别、
                          网关封禁识别、推荐配置）
  mailer/outbox.py        兜底投递通道（导出 .eml/.html、mailto 唤起本机邮件客户端、
                          探测 mailto 默认处理程序）
  mailer/foxmail.py       Foxmail 集成（自动定位主程序、构造唤起命令、
                          用 Foxmail 打开导出邮件 / 弹写信窗口）
  infra/config_store.py   配置持久化（config.json）
  infra/log_setup.py      日志（GUI 窗口 + logs/app.log 轮转）
test_core.py              核心逻辑自测脚本（不启动界面，运行时自建样例台账，
                          不含任何真实客户数据）
```

运行后生成：`config.json`（配置）、`data/sent_records.json`（发送记录）、
`data/holidays.json`（节假日同步缓存）、`data/outbox/`（兜底通道导出的 .eml/.html）、
`logs/app.log`（日志，2MB 轮转保留 5 份）。

节假日数据源：主源 timor.tech（`https://timor.tech/api/holiday/year/{年份}`），
备用源 holiday-cn；同步失败会自动尝试备用源，全部失败时回退到本地缓存/内置数据
并在日志中记录原因（内网环境无法联网时属正常降级，不影响工具运行）。

同步范围：**上月 1 号 ~ 下月最后一天**窗口跨越的年份（最多 2 年）。检查只需判定
"今天是否是某到期日前推 5 个工作日"，用到的日期必然落在今天附近，因此该范围足够。
配置项 `auto_sync_holidays`（默认 `true`）控制"检查前自动同步"。
配置项 `send_mode`（`"smtp"` 默认 / `"client"` 兜底通道）由界面上的"发送方式"单选钮控制，
旧配置文件无此字段时按 `"smtp"` 处理。

配置项 `foxmail_path`（Foxmail.exe 路径，留空则每次启动自动探测）与
`foxmail_mode`（`"auto"` 默认 / `"eml"` / `"mailto"`）由界面上「Foxmail」一栏控制，
改完即时保存；旧配置文件无这两个字段时按"空路径 + auto"处理。

## PyInstaller 打包为单文件 exe

```bat
:: 1. 安装打包工具（开发机执行一次）
.venv\Scripts\pip install pyinstaller

:: 2. 打包（含 chinese-calendar 节假日数据文件）
.venv\Scripts\pyinstaller --onefile --noconsole --name 权限到期提醒 ^
    --collect-data chinese_calendar app.py

:: 3. 产物在 dist\权限到期提醒.exe
```

说明：
- `--noconsole`：双击运行不弹黑色控制台窗口；
- `--collect-data chinese_calendar`：建议保留。当前版本 chinese-calendar 的节假日
  数据以 Python 模块（constants.py）形式随模块自动打包，加此参数可兼容将来万一
  改用独立数据文件的版本；
- exe 是**便携式**的：首次运行会在 exe 同目录生成 `config.json`、`logs/`、
  `data/`，建议单独放一个文件夹；
- 首次启动较慢（单文件 exe 需解压到临时目录），属正常现象；
- 若杀毒软件误报，请加入白名单或改用 `--onedir` 模式打包。

## 常见问题

| 现象 | 处理 |
|------|------|
| 发送失败提示 `timed out`（超时） | **先点「连接诊断」**。最常见的两个原因：① 服务器/端口填错（例如把 443 当 SMTP 端口，标准应为 465 或 587）；② 该地址根本不是发信服务器（如把 `mail.域名` 当成发信服务器，而它只是负载均衡前端）。诊断会查 MX 并逐一实测，给出可用的推荐配置 |
| 服务器"连得上"但发送仍失败 | 典型的**假连接**：TCP 握手被接受却没有任何 SMTP 服务号。诊断的"服务号探测"环节会明确标出，并在"MX 端点"环节找到真正的发信服务器。注意：TCP 能连**不等于**这里有邮件服务 |
| 发送失败提示 `535 authentication failed` | 密码类型不对或客户端策略受限：企业邮箱（腾讯企业邮 / 网易企业邮等）必须用**客户端专用密码 / 授权码**，不能填网页登录密码；自建邮局可能要求生成"客户端专用密码"，或需管理员把你的账号/出口 IP 加入允许范围。点「连接诊断」会按服务商给出具体步骤 |
| 发送失败提示 `(535, b'reject by CACTER gateway, Error: Unknown error')` | **这条 535 是安全网关回的策略拒绝，不等于密码写错**，不要只反复改密码重试。这是国内券商/政企「Coremail + CACTER 网关」组合的典型返回。按成本从低到高自查：① 用浏览器登录网页版邮箱，确认当前密码（工具里存的若是很久以前的初始密码，很可能已过期或被强制更换）；② 网页版 → 设置 → 安全设置/客户端设置 → 生成**客户端专用密码（授权码）**，填到本工具「授权码/密码」框，不要填网页登录密码；③ 确认发件服务器是 **MX 记录指向的主机 + 25 端口（STARTTLS）**，而不是 `mail.你的域名.com`（后者常只是前端负载均衡，会"连得上但没有任何 SMTP 响应"）；④ 若单位启用了客户端白名单，用邮件客户端手工配同一账号发一封测试邮件：**能发 → 白名单策略**，请管理员把本机出口 IP 加入允许范围；**同样发不出 → 回到 ①②**。这条提示会**先探测本机环境再给建议**：若本机没有可用的默认邮件客户端（`mailto:` 无关联），它会明确告诉你这一步在本机走不通，并改为指向「本机邮件客户端」兜底模式 |
| 一时拿不到正确密码，但今天就要发提醒 | 把「发送方式」切到 **本机邮件客户端**：只需目标邮箱，检查时会把含 Excel 附件的提醒导出到 `data\outbox\`，优先用 Foxmail 打开完整 `.eml`，否则尝试系统 `.eml` 关联程序；再次编辑或转发时请使用已配好的单位账号投递。选「否 / 稍后」不会标记已发，下次检查仍会提醒 |
| 怎么把 Foxmail 集成进来 | ① 先安装 Foxmail 并在其中配好单位邮箱账号（能正常收发的状态）；② 回本工具在「Foxmail」一栏点 **自动检测**（会自动扫描注册表、卸载信息、常见安装目录、`PATH`）；③ 点 **测试唤起** 验证——能弹出那封测试邮件/写信窗口即成功。装在非默认位置时用 **浏览…** 手动指定 `Foxmail.exe`。完成后每次检查都会**直接用 Foxmail 投递** |
| 点「自动检测」提示未检测到 Foxmail | 说明这台机器上确实没有 Foxmail 的安装痕迹（本工具会检查注册表三处、卸载信息、常见安装目录与 `PATH`）。若你确定装了，用 **浏览…** 手动指定 `Foxmail.exe`。常见位置：`C:\Foxmail 7.2\`（Foxmail 7.2 安装器默认目录）、`C:\Program Files (x86)\Foxmail\`、`D:\Foxmail\`。提示里若说"检测到 Foxmail 邮件数据目录但没有主程序"，通常是程序装在非默认位置或被卸载过 |
| 点「测试唤起」Foxmail 没反应 | 换一种「唤起方式」再试：先试 **打开导出邮件(.eml)**（最可靠，只依赖"用程序打开文件"），不行再试 **新建写信窗口(mailto)**（依赖 Foxmail 对 mailto 启动参数的支持）。测试邮件会导出到 `data\outbox\`，也可以直接双击它来手工验证 Foxmail 是否能打开 `.eml` |
| 已集成 Foxmail，但还是弹了别的客户端 | 检查「Foxmail 路径」是否有效（点 **自动检测** 或 **浏览…** 重设）。路径无效时工具会回落到系统默认客户端，并在确认弹窗里写明"未使用 Foxmail"。另外可点 **设为默认邮件程序** 打开 Windows 设置，把 `MAILTO` 指定为 Foxmail |
| 不想让工具去动系统设置 | 放心：**设置为默认邮件程序**只负责打开 Windows 的「默认应用」页，真正的修改由 Windows 在用户确认下完成，**本工具不写任何注册表**，也不会改 Foxmail 的配置或数据文件 |
| 切换兜底模式后没弹出邮件窗口 | 正式提醒需要打开含附件的 `.eml`。本机未集成 Foxmail，且没有可用的 `.eml` 关联程序时，工具会打开导出目录供手动投递；可用 Foxmail 等已配好单位账号的客户端打开 `.eml`，再次编辑或转发并确认附件后发送。建议先做上面的 **Foxmail 集成** |
| 兜底模式下弹出的不是 Foxmail | 工具会在提示里写明实际用的是哪一个客户端。若是个人账号的「新版 Outlook」等，**不要用它发**——提醒含客户号与姓名。推荐直接做 **Foxmail 集成**，让工具优先走 Foxmail |
| 不确定该填哪台服务器、哪个端口 | 实测方法：对发件域做 MX 查询，再逐端口探测，**只认真正返回 SMTP 服务号（`220`）的那台主机**。以 `example.com` 为例实测结论：MX = `mailex1.example.com` / `mailex2.example.com`，**仅 25 端口开放且支持 STARTTLS，465/587 均为超时未开放**；`mail.example.com` 则是"TCP 连得上、TLS 也能握手、但不返回任何 SMTP 数据"的假连接。这些都可由「连接诊断」自动完成 |
| 服务器返回 `554 reject by XXX gateway ... Smtp auth error limit exceeded` | 本机**出口 IP 已被对方邮件安全网关临时封禁**（认证失败次数超限）。属 IP 级临时封禁，通常等待一段时间自动解除，也可请邮箱管理员解封。**封禁期间请勿反复重试**（每次都会加重计数）；本工具已内置"失败不重试 + 10 分钟冷静期"来兜底 |
| 提示"已暂停发送：…冷静期" | 上一步账号认证失败后进入了保护性冷静期，避免把出口 IP 送进对方黑名单。确认已修正密码/服务器地址后，**保存邮箱配置**（或一键套用推荐配置）即可立即解除，也可在点"发送测试邮件"时选择立即重试 |
| 提示"目标邮箱格式不正确" | 目标邮箱有笔误（如 `recipient@examplecom` 漏了 .com 的点）。到"邮箱配置"修正并保存即可，这类错误会被提前拦截，不再浪费重试 |
| 测试邮件发送失败：SMTP 认证失败 | 检查授权码（不是登录密码）、端口与加密方式（SSL/STARTTLS/不加密）是否匹配 |
| 提示 Excel 缺少关键列 | 确认同一表头行包含客户号、客户姓名和三项权限到期日期（如“专业投资者到期日期”）；客户编号、客户名称、客户名可作为别名，列名中的空格和换行会自动忽略 |
| 日志显示"无 XXXX 年节假日数据" | `pip install -U chinese-calendar` 升级，或点"同步最新节假日"拉取在线数据；当年会自动降级为仅排周末，不影响使用 |
| 同步节假日失败（网络不通） | 内网/无网络时为正常降级：仍使用本地缓存 + 内置数据；联网后再点一次"同步最新节假日"即可 |
| 日志频繁出现"检查前自动同步有 N 个年份未获取到数据" | 说明当前无网络或该年安排尚未公布（属正常）。若不想每次检查都联网，可取消勾选 **检查前自动同步** |
| 每次检查前都要联网，内网环境能否关闭 | 可以：取消"节假日"区的 **检查前自动同步** 复选框，改为手动点"同步最新节假日" |
| 想重新发送今天已发过的邮件 | 删除 `data/sent_records.json` 中对应条目（或整个文件）后再次检查 |
